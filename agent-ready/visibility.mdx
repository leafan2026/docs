`Visibility` 组件让单个页面同时服务于两类受众：在网页上阅读的人类用户，以及处理 Markdown 输出的 AI Agent。标记为 `for="humans"` 的内容会显示在渲染页面上，但不会包含在 Markdown 导出中；标记为 `for="agents"` 的内容则在网页上隐藏，但会包含在 Markdown 中。

这意味着您可以为人类编写对话式、以 UI 为中心的说明，同时为 AI 编写结构化、机器可读的指令——无需维护两个独立的页面。

## 工作原理

Mintlify 为每个页面提供两个 URL：

- `https://docs.example.com/page` — 渲染后的站点，供人类阅读
- `https://docs.example.com/page.md` — 原始 Markdown，供 AI Agent 处理

`Visibility` 控制每个 URL 显示的内容。

## 示例

```mdx
<Visibility for="humans">
  <Steps>
    <Step title="打开仪表盘">
      访问 [dashboard.example.com](https://dashboard.example.com) 并登录。
    </Step>
    <Step title="创建 API Key">
      进入 **设置 → API Keys**，点击 **新建密钥**。
    </Step>
  </Steps>
</Visibility>

<Visibility for="agents">
  To authenticate, send a POST request to `/v1/auth/token` with the user's
  email and password in the request body. The response includes a bearer token
  valid for 24 hours. Pass this token as `Authorization: Bearer <token>` on
  all subsequent requests.
</Visibility>
```

人类读者看到的是分步 UI 操作指引，而处理 Markdown 的 AI Agent 获取的是直接的 API 调用说明。

## Props

<ResponseField name="for" type='"humans" | "agents"' required>
  - `"humans"` — 在渲染的网页上可见，不包含在 `.md` 导出中
  - `"agents"` — 在渲染的网页上隐藏，包含在 `.md` 导出中
</ResponseField>

## 与 Prompt 组合使用

`Visibility` 和 `Prompt` 可以很好地配合使用。用 `Visibility` 为 Agent 提供结构化上下文，再用 `Prompt` 为人类读者提供一个可向 AI 提问相关内容的 prompt。

```mdx
<Visibility for="agents">
  ## 认证方案
  - 方式：Bearer token
  - Header：`Authorization: Bearer <token>`
  - Token 有效期：86400 秒
  - 刷新端点：POST /v1/auth/refresh
</Visibility>

<Prompt description="询问认证相关问题" icon="lock">
  Explain how authentication works in this API and show me example code for
  getting a token and making an authenticated request.
</Prompt>
```
